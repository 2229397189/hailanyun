# 演示问答手册（TokenArk · 海兰云 POC）

> 用途：演示前 10 分钟过一遍，被问到不慌。
> 原则：**能演示的演示，不能演示的说清边界**。不编数字，不吹未实现的能力。

---

## 0. 开场 60 秒（背下来）

> 这是一套 GPU 算力**运营**平台，不是调度器。
> 底下是客户机房的 K8s，K8s 负责把卡分给 Pod；我们负责 K8s 不管的那部分——
> **谁在用、用了多少、该收多少钱、出问题谁处理**。
> 现在跑的是真集群：平台自己跑在 K8s 里，客户下单也是真的在集群里建 Pod。

三句话讲完，不要展开。展开等他问。

## 4. 三十问三十答

### A. 定位与商业

**Q1 这到底是什么？**
K8s 之上的算力**运营层**。K8s 解决"怎么跑"，我们解决"谁在用、收多少钱、出问题谁管"。

**Q2 客户为啥不直接用公有云？**
公有云按小时贵、卡型不可选、数据出机房。客户自建机房有卡，缺的是运营系统——这正是我们的位置。

**Q3 和 RunPod、趋境这些比呢？**
他们是公有云转售，卡在自己机房。我们是**私有化交付**：装进客户机房，卡是客户的，数据不出网。

**Q4 怎么收费？**
平台授权 + 实施。具体报价不在我这层，我负责技术交付。

**Q5 多久能交付？**
POC 两周（已有一份两周节奏表）；转生产取决于客户给不给真卡和机房权限，见 Q30。

### B. 技术架构

**Q6 整体架构讲一下。**
四层：nginx 接入（TLS）→ Spring Boot 平台（下单/计费/权限/审计）→ K8s（调度执行）→ PostgreSQL + Prometheus/Grafana（账本与观测）。

**Q7 为什么用 K8s，不用 OpenStack？**
客户要的是"一张卡给一个租户跑任务"，不是虚拟机全生命周期。K8s 的 GPU device plugin + 配额 + 调度器现成，OpenStack 做 GPU 透传反而绕。

**Q8 平台自己也跑在 K8s 里？为什么？**
是，`tokenark` 命名空间。好处是交付形态统一：客户机房一套 `kubectl apply` 就起来；且用 in-cluster 认证，不用发 kubeconfig 出去。

**Q9 调度器用的什么？**
清单写的是 Volcano。**但当前验证环境没装**（本机拉不到 GitHub），跑的是默认调度器——所以 Gang、队列配额这些能力**没有实测**，别当成已有功能讲。

**Q10 一张卡能切给两个租户吗？**
设计上支持 1/2、1/4（部署向导有选项），实际**没跑通**：需要 HAMi + 真卡，且 5090 新架构的切分支持还没确认。现在是一卡一租户。

**Q11 多机房 / 多集群呢？**
当前单集群单节点验证。多集群要加集群注册表和跨集群卡池视图，属于下一期。

### C. 真实性（最容易被追问的一组）

**Q12 这些数据是真的吗？**
分三类：**操作链路全真**——登录、下单、建 Pod、释放、计费、审计都落库、都碰真 apiserver；**集群与业务数据在 real 模式是真读**——节点数、卡容量、组件健康、命名空间、版本都来自 apiserver 与 Prometheus；**GPU 硬件曲线目前是模拟或空态**——无卡环境曲线为合成（页上有标注），查询链路已接好 DCGM，有卡即真。一句话：**你点的每一步都发生了，唯一不真的是那条 GPU 曲线，而且它已经为真卡留好了口子。**

**Q13 GPU 温度功耗哪来的？**
分环境：配了 `rental.prometheus.url` 就走 Prometheus 查 DCGM 指标（`DCGM_FI_DEV_GPU_UTIL` 等），DCGM 没上报时给诚实空态并注明原因；没配 Prometheus 时是合成曲线（基数取当前真实占用率叠正弦波，页面注明"演示合成数据"）。真数据要 GPU Operator + DCGM exporter，得先有卡。

**Q14 16 卡是几台机器？**
演示数据是 2 节点 × 8 卡。这是虚构规模，用来展示界面形态。

**Q15 你的 K8s 是真集群吗？**
真的，k3s 单节点，v1.31.4。但**卡是 patch 出来的**：我直接改 Node status 的 `allocatable`，调度器读的就是这个字段，所以调度行为和真卡一致；区别是容器里没有 GPU 设备文件，跑不了 CUDA。

**Q16 我能看看 Pod 吗？**
可以，现在就敲。（**一定让他看**，见动线第 5 步）

**Q17 容器里 `nvidia-smi` 能跑吗？**
不能，会报错。这是这套验证环境的已知边界——验证的是调度、配额、回收，不是算力。要真跑模型必须上真卡。

**Q18 断网了会怎样？**
全内网部署，不依赖外网。镜像走本地 registry:5000，证书自签（可换正式证书，改两个文件重启 nginx）。

**Q19 数据会不会丢？**
PostgreSQL 落卷，`backup` 容器每 24 小时 `pg_dump`，留 7 天。实测重启应用后数据仍在（users=8、租户=6 不变）。生产要加异地备份。

### D. 计费与账务

**Q20 怎么计费？**
单价 2.80 元/卡/小时，下单按全时长**预扣**，释放时按**实际秒数**结算，差额退回余额。

**Q21 预扣会不会多扣？**
不会。预扣只是冻结，结算按秒算，多的一分不少退回。释放接口的返回体里直接给 `actualAmount` 和 `refund`。

**Q22 重复下单会不会扣两次？**
不会。`order_no` 唯一约束，同一单号重复提交直接返回原订单；并发场景还做了回查兜底。

**Q23 余额不足 / 配额不足呢？**
下单前就拦，事务内校验，不产生订单。错误信息带具体数字（"已用 4 卡 / 配额 4 卡"）。

**Q24 客户要发票、要对账呢？**
账单表是按实例的明细分条，可导出。对账文件和发票流程属于财务侧，平台现在出数据不出票。

### E. 权限与安全

**Q25 租户能看到别人的卡和账单吗？**
不能。前端不给入口，后端接口按会话用户过滤；直接敲 URL 会被送回自己那侧。`tenant_a` 只能看 `tenant_a`。

**Q26 密码怎么存的？**
BCrypt 哈希，库里没有明文。被拖库也拿不到密码。

**Q27 运维能乱删东西吗？有审计吗？**
所有写操作进 `audit_logs`：谁、什么时候、对什么、做了什么。可按关键字/动作筛选，可导 CSV。资源对账还能揪出"实例释放了但 Pod 残留"的孤儿。

**Q28 支持等保 / 私有化吗？**
私有化是默认形态（全内网、镜像本地、数据不出机房）。等保要看客户具体等级要求，现在有审计、有权限分级、有传输加密，缺的是正式测评。

### F. 边界与坑（这组答好了最加分）

**Q29 现在最大的短板是什么？**
三条：**没有真卡**，所以 GPU 硬件指标和 CUDA 都是空的；**没有支付通道**，余额是演示账本（MaaS Token 计费是真扣账本余额）；**调度器还是默认 kube-scheduler**，Volcano 的 Gang/抢占/队列没实测。告警已做到规则引擎 + webhook 真实投递，短信/企微渠道要客户给通道才能接。

**Q30 上真卡要改什么？工期多久？**
改三处：装 GPU Operator + DCGM exporter 采真实指标；把卡池从种子数据换成 device plugin 上报的真实容量；接入真实 SSH/Jupyter（cloud-init 注入公钥 + Ingress）。有卡有权限的话，一到两周。

**Q31 5090 支持吗？切分能用吗？**
驱动和 CUDA 层面 5090 没问题；**切分（HAMi）没验证过**，新架构支持情况要实测。别在这里打包票。

**Q32 卡坏了 / 任务卡在 Terminating 怎么办？**
卡坏了可以点"标记故障"，从可售池摘除，修好再回池。Pod 卡 Terminating 时释放会失败，实例停在 `releasing`——**卡不释放也不重复计费**，巡检会重试补删。这是故意设计的：宁可账面对不上，也不能"账面已释放、卡还占着"。

### G. 新增功能组（2026-11-04 补齐，最可能被现场点）

**Q33 折扣和券是怎么算的？**
下单金额 = 卡数 × 时长 × 单价 × 折扣叠加（闲时 5 折 × 学生 9 折 = 4.5 折），优惠券独立于余额展示、下单时可用。所有口径都写死在测试断言里（51 项实测），演示时直接点一个闲时+学生账号下单，看预扣金额即可。

**Q34 升降配丢数据吗？**
升降配是换实例：旧实例到期保留 7 天（停止计费），新实例立即开；克隆会复制原实例的镜像和挂载配置。定时关机到点由平台自动执行，不依赖浏览器。

**Q35 命令行能用吗？**
能。`deploy/cli/ark-cli.py` 纯标准库，登录、查套餐 / SKU / 余额、实例开关机、续费、释放结算一条龙，输出 usedSeconds 和退款。这给客户运维脚本化留了口子。

**Q36 挖矿怎么防？**
登录页协议明示禁止；巡检自动巡逻利用率满负荷的卡，生成 P1 项并给出"核对任务特征、确认即冻结并按协议追责"的处置建议。平台提供的是治理手段，不是检测保证。

**Q37 经营报表数字是真的吗？**
管理端「经营报表」的收入曲线、券核销、租户余额都是从订单/账单/券表实时聚合，和库里的数对得上。演示前可以先跑一遍 51 项测试把口径坐实。

## 5. 被问住时的兜底话术

不要现编。三句里挑一句：

1. **"这个点我没做过验证，回去查了代码再给你准确答复。"**
2. **"设计上是这样，但当前环境没实测，我不能当结论讲。"**
3. **"这属于下一期范围，现在给不了时间点。"**

编一个数字被当场戳穿，比说"不知道"损失大得多。
